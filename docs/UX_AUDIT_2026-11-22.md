范围：学习者前台目标规划 / 学习台 / 学习路径 / 课堂 / 学习状态，后台虚拟学习者启动，以及 Agent/Skill 功能可用性与效果证据边界。方法：隔离本地环境（独立 SQLite + 独立端口 3341/5173，`doc/local/ux-audit-20261122/`）真实 GUI 走查 + 三个只读代码审计 + 契约/回归测试。截图存 `gui-test-screenshots/`（gitignored），本文只留结论与代码位置。

## 一、本轮已修复（均已验证）

### 学习状态页（V2LearningState.vue）
1. **读取失败/读取中不再冒充「还没学过」**：原 `stateEmpty = !hasAnyLoad && !hasKpiData` 在请求未返回或读取失败时也成立，新用户会看到「学习状态正在积累中」并把服务故障当成「我没学过」。现区分 `loading / error / empty`：只有各数据源成功返回且确无记录才显示空态（新文案「还没有可分析的学习记录」）；sessions/mastery 失败给独立告警卡 + 「重新读取」。
2. **未观测日不再补 0 判「需要休息」**：趋势序列原来把首次数据前的日期补成 0 并过 `zoneOfLsb(0)` → 展示成一次确定的「需要休息」判断。现缺失日保持 null，单日数据靠图上实点表达；历史值读数对无状态日显示「该日暂无状态记录」，时长读取失败显示「未读取」而非 0。
3. **「采用建议」改为先确认**：卡头按钮原来直接发 replan 请求（绕过逐条卡确认），且同一按钮可能改路径也可能只是跳页。现统一为「查看并确认调整」→ 内联确认块显示**实际执行范围**（按 `advisory.scope/targetStageNumber` 显示「第 N 阶段」或「第 N 阶段及之后的未完成阶段」）→ 确认后才发请求；回执区分 `accepted`（后台执行，提示去路径详情看进度）与 `redesigned-stage`（已完成），409 冲突给出清场指引，失败保留建议卡可重试。

### 目标规划页（V2GoalConversation.vue + useGoalLive.ts）
4. **首轮失败不再谎报「连接失败」**：按服务端明确错误分类（模型未配置 / 传输中断 / 超时），未知失败只说「你的消息已保留，但尚未收到 AI 回复」，输入气泡不丢。
5. **等待文案不再编造进度**：原来按秒数轮播「正在拆解阶段…/排布任务…/正在收尾…」，前端无从得知真实阶段。现只说「正在生成方案…/仍在生成…/比预期更久，可先停止等待」。
6. **「停止生成」改为「停止等待」**：实现只中止本页请求、不取消后台任务，文案与行为对齐；停止后错误条改「已停止等待回复。已提交的生成可能仍在后台继续」+「查看最新进展」（有会话时走服务端快照回读，实测有效）；无会话时「重新开始」。停止期间输入框禁用并说明原因。另修复：非流式回退请求无法被停止（`waitForFallback` 包装）、超时/停止会落两条错误消息、停止后仍可继续发送。
7. **「清空重聊」改为「开始新规划」**：旧确认弹窗说「记录将被删除，不可恢复」，实际云端会话与最近会话入口都还在。新文案如实说明「已保存的会话仍可从最近会话或原链接打开」，去掉危险色。
8. 入口页副标题给具体示例并写明「AI 先澄清，你确认方案后再生成路径」，校准对 AI 的预期。

### 学习台与路径（V2Dashboard / V2LearningPaths / V2LearningPathDetail / learningPathProgress.ts）
9. **失败类型与动作对齐**：首页固定「这版路径没生成出来，重试一般能好」且按钮一律「重新生成路径」，而 `retryType=stage_design` 实际是课程准备。新增共享 `buildGenerationRetryCopy`（`frontend/src/views/v2/learningPathProgress.ts:43`），三个页面按真实失败类型命名动作，去掉「一般能好」的承诺；提交成功只说「已提交…请求」，并立即回查状态。
10. **「只看核心主干」隐藏数修正**：原来统计所有 flexible 任务，但某阶段全为 flexible 时实际一个都未隐藏。现按「渲染前 − 渲染后」实算，并注明「仅筛选显示，不改变学习安排与完成要求」。
11. 起步卡「用 2 分钟，理出一条能执行的路径」改为「先说说想解决的事，一起确认怎么学」，说明确认与渐进生成预期，不承诺时长。

### 课堂页（V2LearningPage.vue）
12. **契约卡说人话**：「本节契约 / 核心 KC / 独立证据 / 停车区」→「本节完成要求 / 已验证 N/M 个重点 / 独立答对 N/M 个知识点 / 留待课后探索的问题」；课末终检状态与输入框占位按真实场景（待独立作答时提示写答案和思路）。
13. **完成受阻提示列出真实缺口**：不再笼统「继续完成课堂契约要求的检查与证据」，按契约账本逐条列「还有 N 个重点没有验证记录 / 还需独立答对 N 个知识点（不靠提示）/ 课末独立作答还没通过」。

### 教学后端（效果评估可信度）
14. **重答不再被计成「首答独立成功」**：`teaching-turn-engine.ts` 为当轮契约临时构造的检查点证据原来写死 `attempts: 1`，点拨后第二次答对会被当轮报告计为独立证据（结算门读取该报告）。现当轮契约与持久化历史复用同一份作答元数据（真实累计次数 + 概念归属 + `answerAlreadyGiven`），`lesson-contract.ts` 的独立计数同时排除「教师已给过答案」的复述成功；新题无提示首答仍可独立。
15. **课堂契约/报告/终检/支线随回合下发**：`ai-teaching.routes.ts` 的消息响应白名单原来丢弃 `lessonContract/lessonReport/exitTicket/branch`，前端实时收不到、只能刷新后从 `/detail` 补回。现四个字段进公开 DTO（`ai-teaching.routes.ts:626-629`），答案键沿用 `/detail` 同一把 `stripCheckpointAnswerKeys` 深剥离，不泄露裁决键。

### 虚拟学习者启动（后台）
16. **黑盒「已开始运行」不再假报**：`start-blackbox-session` 原来只创建 `status=created` 会话就返回，前端因缺 `autopilot` 字段走默认分支报「已开始运行」。现复用 `startSessionAutopilot`：缺省 `off`（旧脚本约定不变，仍只创建），后台 UI 显式传 `final`；回执按 `started/queued/failed/off` 如实反馈，前端各分支配真实文案（并发满=已排队、失败=可到画像页重试、仅创建=未启动）。运行模式补一行说明（辅助支持模拟日期；黑盒走真实接口、用真实日期，独立评审在会话审计发起）。新增契约测试 `backend/src/routes/admin/__tests__/virtual-learners.blackbox-launch.test.ts`（17 例）。

17. **裁判技能守卫与编译稿对齐**：`prompt-realism-guards.test.ts` 仍锁「R1 豁免」旧措辞，与上次提示词重生成后的「R1 无路径收口…无路径可以是合理结果」冲突（存量全量失败）。断言已更新到现行口径。

## 五、外部评审方案修复批（2026-11-22 第二批）

外部工程评审给出 P1.1–P3.4 逐项方案，本批逐项核实后落地（其中三项按实际代码形态做了适配，见各条「适配」注）。按「止血数据污染 → 评测防假过 → 前端可见性 → 运维与闸门」分两批实施。

### 数据污染止血（P1.1）

**B1 · 延迟保持探针/课堂温故去重引入独立作答身份。** 原去重键（用户+会话+概念）会把 48-72h 后的真实新作答当重复吞掉但报已降级。现事件 payload 携带 `reviewAttemptId`（探针用 `probe.id`，`retention-probe.service.ts`），消费端只与**同一作答身份**的既有行去重，不带身份的旧事件保持原行为（`ReviewCompletedConsumer.ts:97-123,205,223,304`）。**适配**：不改 evidenceKey 行身份——`ConceptConsolidatorService` / `review-plan.service` 有两处 exact-key 读方依赖现有键族，改行身份会破坏记忆合并与复习计划回读。新增 `ReviewApplySummary`（totalItems/appliedItems/skippedDuplicateItems/skippedNegativeInterval），`answer()` 按 `appliedItems` 判定真实降级并 warn 留痕。回归：`ReviewCompletedConsumer.test.ts`（重放去重/新身份放行/负区间跳过）、`retention-probe.test.ts`（全跳过时不得报已降级）。

### 黑盒评测防假过（P1.3/P1.4/P1.5）

**B2 · 黑盒 Goal 学习者离场即离场。** 模拟器输出 `shouldEnd/endReason`（leaving|satisfied|declining|no_more_questions）此前被 runner 丢弃，学习者明确离场后仍被继续驱动。现 Goal 分支在确认门之前消费离场信号：走 abandon 动作、`exitReason` 并入 control（`contracts.ts:110` `learnerExitReason`、`blackbox-runner.ts:896`），离场原因截断 40 字落 `learner-exited:<reason>:…`。回归：`blackbox-runner.test.ts` 4 例（离场不再追问/reason 落库/无 abandon 动作时不误退/原因截断）。

**B3 · 裁判逐维实质证据门。** 原只引用 `observation.stage`（只证明「跑过该阶段」）即可 pass。现 `REQUIRED_STAGE_BY_DIM`（`simulation-referee/index.ts:168`）要求四个体验/理解主维度各有对应阶段 publicTrace 的**非 stage 字段**证据，缺维进 `integrity.missingDimensionEvidence`（`contracts.ts:236`）并强制 verdict=inconclusive + evidenceSufficiency≤45；`softValidateParsedOutput` 给出含缺维清单的定向重试原因（`index.ts:294`）。回归：`simulation-referee/__tests__/index.test.ts` 判例翻转。

**B4 · memory-curate 空数组不再回退自评掌握。** 模型合法返回空 mastered 列表时，原 fallback 会用「自评完成」生成 0.7 信心掌握印象。现 fallback 只产空数组（`simulation-memory-curate/index.ts`），normalize 仅在字段确实缺失时才降级（`masteredGiven`/`struggleGiven` 区分「给了空」与「没给」）。回归：判例翻转。
