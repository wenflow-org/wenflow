# 无人化 20 用户压力测试（2026-11-13）

> 触发：用户要求「用 20 个用户优化平台存在的问题，过程无人化；本地起分支，改动不直接提交 develop；case 必须是纯文本模型教学能力范围内的（不要美术/绘画等物理活动），且避免一节课就上完」。
>
> 分支：`feat/unattended-20case-sim`（所有 campaign 产物与修复都留在本分支，不合并 develop）。

## 一、这轮要回答的问题

不是「平台能不能跑通」，而是**在 20 个互不相同的真实学习目标下，平台会不会暴露同一类结构性缺陷**：

1. **Goal 收敛**：模糊目标（「想会说话」「想看懂经济新闻」）会不会被收敛成可排课的复合能力，而不是一节课打发、或反复追问不收敛。
2. **路径形状**：复合目标是否稳定产出 3+ 阶段、8+ 课时的多节课路径；有没有被压成 1-2 节「慢镜头拆课」或 4 阶段 15 节的虚胖路径。
3. **材料依赖**：法律/财报/论文/统计/时事类目标是否真的触发联网取证；引用是否带出处、是否把示例当学习者经历。
4. **课堂质量**：开场是否泄漏答案/标题剧透、板书与讲解是否对得上、图文是否错位、长会话是否截断失明。
5. **纯文本边界**：明确说「不写代码/零基础」的目标，是否被塞进安装环境、跑代码、动手实操；反过来，纯文本可教的目标是否被误判为物理边界而拒教。
6. **长程连续性**：跨天/跨阶段是否记得前序、复习是否接得上、卡点是否来自真实误解而不是模型臆造。

## 二、用例设计原则

### 1. 纯文本可教（硬约束）

只选**知识理解、文本分析、判断决策、写作产出**四类能力。排除：美术/绘画、乐器演奏、体育动作、烹饪、实验操作、硬件维修、软件安装等必须动手或依赖物理环境的领域。

两个边界用例专门验证：
- **u17 HTTP 缓存与并发（不写代码）**：产品经理明确拒绝学代码，目标仍是概念理解与评审提问能力。
- **u13 公共演讲讲稿**：只做讲稿与结构设计，不要求上台演练。

### 2. 避免一节课上完（硬约束）

每个目标都写成**复合能力 + 可交付物**，而不是单一知识点：

- 「看懂劳动合同」→「独立审查五类高风险条款并写出修改建议」
- 「学财报」→「读懂三张表 + 判断经营质量 + 识别三类造假信号」
- 「练表达」→「五类高压职场场景各写一封可执行邮件」

路径规划器若把这类目标压成 1-2 节课，本身就是本轮要抓的缺陷。

## 四、执行方式（无人化）

- 复用 `backend/src/scripts/simulate-learner-e2e.ts`：每用户一个可丢弃虚拟学习者 + 会话级模拟时钟 + `--realistic-persona`（拟真人设带摩擦）+ 逐步驱动 goal + 逐日 `advance-day`。
- 新增 `backend/scripts/run-user-campaign.mjs`：读用例 JSON，按并发度拉起 20 个 harness 子进程，逐 case 写日志/状态/结果，支持断点续跑与失败重试；产物落在 `backend/.runtime/campaigns/<batch>/`（gitignored）。
- **全程 `--keep`**：保留虚拟学习者与会话，供采集脚本读取路径形状、课堂消息、材料调用；批次结束后再统一清理。
- 新增 `backend/src/scripts/report-user-campaign.ts`：从 Prisma 读取每个 session 的路径阶段/课次/时长、课堂会话/消息数/开场、goal 收敛状态、findings，输出批次报告。

### 批次

1. **试点（4 case × 1 天）**：u01（材料+法律）、u04（财报+数字）、u17（禁代码）、u19（模糊目标）。验证 harness、用例措辞、路径形状初判。
2. **全量第一批（20 case × 7-9 天）**：并发 5 起步，观察 429/租约/耗时后再调。
3. **修复批**：按 findings 聚类，在本分支修复并定向测试。
4. **回归第二批（20 case）**：同用例重跑，对比 goal 收敛率、阶段数、课时数、材料引用率、课堂失败率。

## 五、失败分类（采集口径）

| 类别 | 判据 |
| --- | --- |
| goal 不收敛 | `goal-not-converged` / 20 步仍在 goal |
| 路径未生成 | `path-generation-failed` / `path-not-ready-timeout` |
| 路径虚胖/过短 | 阶段数 <3 或课时 <6；或 >6 阶段/>18 课 |
| 材料缺失 | 有材料依赖的目标无联网记录/无出处引用 |
| 课堂失败 | `session-failed` / 教学回合暂停 / 空开场 / 消息为 0 |
| 纯文本越界 | 目标被塞进安装/跑代码/动手实操；或纯文本目标被拒教 |
| 长程断裂 | 跨阶段开场复述错误/不接前序/重复上一课 |

## 六、试点观察（2026-11-13 第一轮）

1. **管理员并发登录互踢（跑数器缺陷）**：4 个 harness 各自登录，管理员登录按 ip+User-Agent 吊销兄弟会话，3/4 个 case 在创建学习者时 403「会话已吊销或过期」。修复：runner 预登录一次，把 `E2E_ADMIN_COOKIE` 传给所有子进程；harness 支持复用。修复后 3 并发全部正常建号。
2. **拟真人设身份漂移（平台缺陷，待修）**：`generate-persona` 收到 case 身份种子后，仍会生成完全无关的人设——「签劳动合同的产品经理」→「烘焙工作室主理人」，「看财报的运营」→「汽修学徒」，「产品经理学缓存」→「大理民宿店长」。提示词有「保留 existingPersonaSeed 底色」规则，但被「避免最近职业重复」的自由采样规则压过。跑数器先做身份锚定（保留生成的情绪/失败/时间行为字段，name/occupation/background 锚回 case）；平台侧需要确定性锚定或提示词加固，记入修复批。
3. **路径生成耗时**：4 阶段路径从 goal 完成到首课可用约 23 分钟（core → 逐阶段 design ×4 → KC 映射 → 落库）；stage-designer 单次 70-170s，阶段设计并发度为 1。批量跑数把 `--ready-timeout-ms` 放宽到 60 分钟，避免把「慢但正常」误判为未就绪。
4. **路径形状符合预期**：模糊目标「想变会说话」收敛为 4 阶段 / 8 课 / 1.5h，标题具体、无结论剧透；goal 7 轮结束（4 条用户消息），中间接住了「每天下班写代码到十点、只能在吃饭路上刷」的时间约束，改成 10-15 分钟微课，并排除了通用台风/声音控场。
5. **待确认的课堂现象**：单日 `advance-day` 在完成 1 课后又开了一节新课，只落了开场 1 条消息就停在 active；需在 7 天批次里确认次日是否能正常续上，还是重复开场/空转。
6. **材料采集口径**：u19（无材料标签）collector 调用 0 符合预期；法律/财报/论文等材料型 case 要等全量批次验证是否真的触发。
7. **answer_then_hook 吞掉打字确认（平台缺陷，已修）**：u01 被分诊为 `answer_then_hook`（签约当天、一次性操作）后，`answerOnlyGate` 同时跳过了确认裁决，打字「好，那就开始吧」既不算 confirmIntent、也进不了 `answerOnlyNudges` 计数。学习者连续说三次「开始排吧」后直接离场，`goal-ended-without-path`。修复：answer-only 闸也先跑裁决；「坚持 ≥2 次」改为累计确认意图（含本次），第一次直答、第二次放行。新增单测 `goal-conversation.confirm-intent.test.ts` e)。需重启后端生效。
8. **拟真人设漂移的平台修复（已写，待重启）**：新增 `services/virtual-lab/persona-identity-anchor.ts`，在 `generate-persona` 与 `draft-profile` 出口只锚身份字段（nameHint/age/occupation/education/background），行为字段保留模型生成；单测覆盖换身份/只给名字/无 seed 三种情况。

## 八、批次结果与迭代（2026-11-13）

### 第一批（20 例，全部跑完）

- **完成 5 / 未跑完 14 / goal 未收敛 1 / 失败 0**。19/20 生成路径，平均 **2.8 阶段 / 10.8 课 / 4.4h**。
- **无一节课风险、无标题剧透、无阶段内只剩 1 课、无课堂失败/空会话、无开场假定经历**。
- 材料：10 个 case 触发了 material-collector；仍为零采集的 4 个是 u01/u02（只声明私有合同）、u07（私有论文）、u10（未生成路径）。
- u10 的 `goal-ended-without-path` 是真实缺陷：6 个 AI 回合持续追问、不产提案，时间紧张的学习者离场。
- 14 个 `max-days-reached` 不是产品失败：路径 10-18 课，7-9 个模拟日只跑到一半；说明路径长度普遍超出短期冲刺型学习者的时间预算，但满足「多节课」约束。

### 第一批修复（已提交本分支）

1. 管理员并发登录互踢 → runner 共享 Cookie。
2. answer_then_hook 吞打字确认 + off-by-one → 裁决照跑、累计 2 次放行。
3. goal→path 交接只读最后一轮 → 改累计 understanding。
4. 仅声明私有材料时跳过公开派生 → 合并派生公开 need。
5. 研究价值词缺财报/合同/判例等 → 补齐；长句目标压出领域检索短语。
6. 拟真人设无视身份种子 → 确定性身份锚定（保留行为字段）。
7. ≥5 个用户回合仍无提案 → 收敛窗口软校验强制重试。

### 第二批（同 20 例，验证修复）

- u01 首课即闭环（19min，4/4 课），材料调用 **0 → 1**（上海市人社局页面，partial），证明「私有合同 + 公开法条」补位生效。
- u02 20min 闭环（第一批 26min），材料仍 0：其 `keyStages` 未透传、语料只命中「合同」1 个信号，研究价值闸在无阶段名时要求 ≥2 → 追加「强领域词单独命中即采」与 `rawGoal` 兜底，待第三批定向验证。
- **u10 已不再零路径**：goal 3 轮收敛、stage=completed、生成路径；第一批的 `learner-left` 没有复现。收敛窗口软校验（≥5 轮强制重试）作为确定性兜底保留。
- 本批速度明显慢于第一批（单日 4-13 分钟），provider 在 5 并发课堂下排队；不影响结论，但说明批量跑数应按 provider 容量控制并发。
- **路径体量方差**：同一 case 两次运行的路径形状差异显著——u05 第一批 2 阶段/4 课/0.8h，第二批 4 阶段/15 课/7.5h；u06 3/12 → 4/14；u07 3/14 稳定。goal 收敛的「范围大小」仍受拟真人设的可用时间/表述影响，缺少跨 run 的稳定性护栏。这是下一轮优先级最高的产品问题（不是本轮修复项）。

### 第三批（定向，已跑）

- u02 / u03 / u07 / u10，2 个模拟日：4/4 生成路径；材料调用 **u02=1、u03=1、u10=2**，u07 首跑仍 0。
- u07 归因：goal 输出 `needsMaterial:{}`（空对象）被当成「已声明公开需求」，压掉了派生；补「空对象不阻断派生」+ 论文/文献/学术词库后单跑，**material 0 → 1**。
- 至此材料链路在真机上验证：u01/u02/u03/u07 从 0 到 1，u10=2，u15/u16/u18 原本就能触发。

## 九、非目标

- 不追求 20 个 case 全部完成到最后一课；目标是**在有限天数内暴露结构性缺陷**，而不是刷完成率。
- 不把虚拟学习者的拟真度当成产品质量结论；拟真人设只是加压手段。
- 不在本分支合并/推送 develop；所有改动留在 `feat/unattended-20case-sim`。
