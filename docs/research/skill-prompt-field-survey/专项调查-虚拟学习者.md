## 0. 结论速览

1. **业务上，虚拟学习者是「零真实成本的教学/路径缺陷暴露器」**。2026-11-13 起的批跑战役证明其最大产出其实在**教师侧**：referee-minibatch 的最大失真簇（WRAPUP_MASTERY_OVERCLAIM major×8、板书固化学员错误 critical、OPENING_ASSUME_EXPERIENCE 5/5）几乎全是平台教学链的缺陷，而非扮演侧的。 learners 侧最大残留是**跨 run 路径体量方差**与**离场/重复两类结构问题**。
2. **阶段对接**：双轨（assisted 状态机 / blackbox 命令机）生命周期与 7 类终局判据基本闭环；但存在 **12 条对接缝风险（H×2/M×6/L×4）**，其中两条 H 级（摩擦反馈闭环三处落空、离场终局仅 autopilot 消费）与扮演侧 V-D1/V-D2 同源——**离场信号在编排器通用入口与黑盒轨不被消费**。
3. **扮演对话**：26 条机制六族编目，2026-11-11 修复 **13 项确认落地**（多数带测试锁定）；残留 **9 条向量**，最重两条是新发现：blackbox 链丢弃 `shouldEnd` 且按 `readyToAdvance` 代发确认提案（与 assisted 已废除的代签语义不一致）、手动/auto 入口可让已离场学习者复活空转烧预算。
4. **模仿人类**：平台在**记忆层**（四态代码裁决/私有状态解耦/能力悖论防御）领先外部角色扮演产品；在**语言学层**（无 disfluency 设计、AI 惯用语无清洗）、**节奏层**（无延迟/打断工程）、**心理层**（help abuse/avoidance 行为统计未建模）是空白。核心外部结论：人味 = 分布对齐 + 可控破绽，不是更流畅。
5. **外部对照**：49 条外部机制（SillyTavern/NovelAI/AI Dungeon/Character.AI/RisuAI/星野·Talkie + MemGPT/Mem0/Zep/Letta/数字人栈/Inworld/Neuro-sama/AI Town/Nemesis），合并出 **10 个 H 级迁移主题**，多数可直接映射到已知失真模式。

## 1. 业务切入点（先从业务上看）

虚拟学习者的业务本质：**在真实用户付费/消耗注意力之前，用可控成本复现「分群用户 × 真实故事」的完整学习旅程，把缺陷在实验室内暴露出来**（对应文献中的 risk-free simulation 定位，lit-07 [2]）。按当前成熟度排序列出六个切入点：

| # | 切入点 | 业务价值 | 当前成熟度（证据） | 主要矛盾 |
| --- | --- | --- | --- | --- |
| B1 | **教学质量回归与 KPI 治理**（referee 三体验评分） | 已验证最高价值：referee-minibatch 病历单产出的最大失真簇全在教师侧（wrapup 掌握度虚标 major×8、板书固化学员错版 critical、答案提前暴露）——直接反哺教学 prompt 迭代 | 中高：批 A~N 已跑通、多条 critical 已修 | 裁判输入截断（22 条轨迹被截）、finding code 同一现象 8 种写法、裁判曾长期 0 调用 |
| B2 | **发布前回归验证**（20 用户自动驾驶战役、批跑 harness） | 上线前暴露 goal 收敛/路径生成/课堂链路缺陷（u10 追问不收敛、answer_then_hook 吞确认均为真机缺陷） | 中：第一批完成 5/20，负证清单良好 | **跨 run 路径体量方差**（u05 2阶段/4课 vs 4阶段/15课，被定性为下轮最高优先级）；max-days 错配（14/20 报 max-days-reached） |
| B3 | **人设资产库 = 用户分群覆盖** | presets（9 条×40 字段满配：身份/认知/动机/情绪/行为/场景六面）即「分群语料」，一次投入多战役复用 | 分层严重：presets 满配 → cards 200 张仅 4 字段 → --realistic-persona 随机+锚定兜底 | **失真集中发生在行为字段最薄的一侧**（身份漂移 5/5 全漂发生在 generate-persona 链路）；行为字段是扮演质量的第一杠杆 |
| B4 | **扮演保真治理**（actor-audit 7 维评分） | 回答「这个像不像人、哪轮漂了」，是 B1/B2 结果可信的前提（保真不达标的教学评分无效） | 低：能力已建但 qa-reports 记录累计 0 调用史；assisted 链无调用点；事后单轮审计无跨轮窗口 | 审计投入与产出的正反馈未建立 |
| B5 | **归因分流**（学习者困难 vs 平台缺陷） | referee 归因字段 + stuck 归因 append-only 已把「为什么卡住」变成可答问题（2026-10-21 后归因不再丢） | 中：GOAL_STUCK_LOOP、F_001 abandon 误报均已修复归位 | 归因字段与 classroomContext 证据的交叉校验仍薄弱 |
| B6 | **课程/材料压力测试** | 暴露材料链缺陷：PHANTOM_TRANSFER_MATERIAL（引用不存在的摘要）、二手源误信（豆瓣书评 status=ok）、needsMaterial 空对象压掉派生 | 中：critical 已转观察+tripwire | 采集触发 ≠ 证据质量；一手源优先/域名限定未做 |

**业务切入点结论**：当前投入产出比最高的动作是 B1（裁判观测面修复：全量轨迹输入 + code 规范化）与 B3（cards 行为字段富化）——前者直接提升全部战役的信号质量，后者直接压身份漂移；B2 的跨 run 方差是产品级问题（影响「演练结果能否比较」这一前提），需要在 goal 收敛口径上做稳定性护栏。B4 需要一次「接线」而非新建（把 actor-audit 接进 assisted 链与战役默认流程）。

## 2. 体系架构与阶段对接问题

### 2.1 双轨生命周期（详见 _vl-01 §1）

- **assisted 轨**（`coordinators/simulation.coordinator.ts` 状态机）与 **blackbox 轨**（`virtual-lab/blackbox-runner.ts` 命令机 + Idempotency-Key 幂等 + 冻结快照）互斥，由 `stageResults.experiment.mode` 区分。
- 驱动者 9 类（驾驶舱手动、教学面、path 评审面、黑盒实验面、autopilot、advance-day、harness、批量矩阵、回收终止）；终局判定 7 类（learnerEnded / repetition-loop / noPath / completed / failed / abandoned + 可续跑暂停），另有 5 项兜底护栏（预算耗尽、重规划上限、无进展看门狗等）。

### 2.2 persona 供给链

四来源（管理台手建 / persona-designer 生成 / 草稿面 / presets+cards seeder）→ `virtual_learner_profiles.profile` JSON → 进 prompt 三条路：**actorProfile 5 件套整包** + **wrapper 合成的 `friction`/`personaAnchorHint`**（后者是平台常量 `PERSONA_FIELD_ANCHORS_HINT`，点名 10 个锚点字段，编排层从不传该键）+ **storyPool→storyHistory 深投影**（防串场泄底，已闭环）。

### 2.3 三大阶段对接缝要点

- **goal**：goal-dialogue 消费 story/visibleContext/currentPhase/previousLearnerState/learnerMemory/frictionBudget；输出 `shouldEnd` 由 assisted 消费为终局、**blackbox 不消费（V-M2/V-D2）**。
- **path**：path-evaluate 的输入来自平台库表（learning_paths/milestones）而非 stageResults；**blackbox 轨不跑 path-evaluate**（评审证据链缺失 V-M1）；`goalState` 声明但恒 null（V-M6）。
- **teaching**：learn-turn 15 输入三方（yaml 声明↔assisted↔blackbox）逐项对齐；受控错误编排层采样 + 判决器不服从时代码强制覆写（`forcedCorrectness`→`sampledCorrectness:false, masteryProb:0.15`）；checkpointAnswer↔checkpointVerdict 两轨闭环；模拟器不消费教师侧专用键（scenario/interactionProfile/checkpointVerdict 结构键），教师判卷以自然语言回传可见历史。
- **日期与时间感**：`simulationClock` + AsyncLocalStorage 同钟写读 → `temporalContext` 注入 learn-turn → dayIndex 驱动 FSRS 到期面 → `dueReview`/`memoryRecall` 四态确定性裁决；黑盒显式禁日期模拟防双钟。

### 2.4 对接风险清单（12 条，摘录；全文见 _vl-01 §5）

| 编号 | 级别 | 风险 | 后果 |
| --- | --- | --- | --- |
| V-H1 | H | TIR 摩擦反馈闭环三处落空：actor-audit 上调的 frictionBudget 写入 `simulationConfig`，但 blackbox 运行中读冻结快照、rerun 也取快照原值，唯一读 simulationConfig 的 assisted 轨又不产生 TIR 评估 | 校准反馈通道整体死写，B4 切入点无法自进化 |
| V-H2 | H | `learnerEnded`/`noPath` 只被 autopilot 消费；`executeAutoLoop`/`executeFullSession`/`/step`/`/auto` 不识别 | 离场学习者被驱动到 maxRounds，每轮白烧 2 次 LLM 调用；learner-ended 误报成「未收敛」 |
| V-M1 | M | blackbox 不执行 path-evaluate | 两轨「路径接受」语义不可比，审计无法区分评审后接受与直接开课 |
| V-M2 | M | blackbox goal 轮丢弃 shouldEnd/endReason | 「像真人一样离场」在黑盒轨结构性不可达 |
| V-M3 | M | referee 与 actor-audit 输入互不包含，且双评估串行一损俱损 | 保真证据与合规裁决无法交叉引用；referee 抛错连 actor 报告都不产出 |
| V-M4 | M | friction（wrapper 采样）与判错（编排层采样）双点双掷、无结构化留痕 | 「触发对抗的轮未必判错」，跑批统计靠文本反推 |
| V-M5 | M | personaSeed 31 字段整包进 payload 但锚点常量只点名 10 个 | personalityDrivers 等设计者声明为 friction 依据的字段未被点名消费 |
| V-M6 | M | path-evaluate 的 goalState 恒 null | 评审器对「当初谈定的方案」失明 |
| V-L1–L5 | L | 检查点中断窗口差一轮（产品决策留痕）、终态分桶对齐、时间感注入面不对称（有意）、开场绕过模拟器（防白烧）、冻结路由只套主叙事器（判决器旁路→判决-叙事可能异源） | 已知受控残留 |

### 3.2 跨轮状态连续性

9 类状态读写链主闭环（story/learnerMemory/previousLearnerState/四态/画像概念均有明确归属）；三个**方向性缝隙**：friction 每轮独立重采样无惯性（V-D3a）、concernPool/disclosedConcerns 算而不喂（V-D3b，死状态）、learnerEnded 无入口闸（V-D1，状态只进不出）。

### 3.3 确定性护栏（12 项）

总评：goal 离场三重防线（模型主信号 + 三字组兜底 + autopilot/harness 停条件）完整**但只覆盖两个驱动方**；learn 能力悖论防线（判决→钳制→审计）最厚；话语风格类规则（离场字数/emotion 一致性）在 goal 侧基本无代码兜底。prompt-realism-guards 回归测试 24+ 断言锁规则文本。

### 3.4 修复核验与残留向量

2026-11-11 修复清单 **13 项已落**（shouldEnd 进 fields 表/outputSchema、离场纪律、单驱动、身份锚定、noPath 双路径等，均带测试），2 项 audit 自认残留未动（语义看门狗、paused 语义），1 项部分落（persona 显式种子）。残留 **9 条向量**（V-D1 入口闸、V-D2 黑盒 shouldEnd+代签〔高〕、V-D3 摩擦白噪声+关切死状态、V-D4 emotion 无枚举校验、V-D5 patience/enthusiasm 无话语锚点、V-D6 换话题不走看门狗缺、V-D7 CONFUSED 态因混淆池空置不可达、V-D8 开场确定性模板化、V-D9 兜底仍是模板人种子）；另排除 4 条疑似向量（learn 无摩擦、四态模型自判等均不成立）。

### 3.5 失真模式证据（10 类，详见 _vl-03 §2）

离场（21 轮告别循环写进测试用例名；learn 无离场语义仍未修）／重复复读（学习者与教师双向）／身份漂移（战役 5/5 全漂→persona-identity-anchor 修复）／泄露（NOTATION_LEAK 6/7、答案提前暴露）／误诊误判（情绪硬阻断、scope_size 钳塌缩、answer_only 吞确认）／节奏（出题节奏票、单轮多概念块）／情绪掌握度失真（WRAPUP_MASTERY_OVERCLAIM 最大簇；「19 连对零失手」）／记忆经历虚增（OPENING_ASSUME_EXPERIENCE 5/5）／材料悬空（PHANTOM_MATERIAL critical）／扮演-教学机制冲突（epistemic 只看静态人设、白板不进 visibleContext——均已修）。

## 4. 如何模仿人类：五层判据对照（详见 _vl-04）

外部核心结论（[31]–[43] 补充 lit-07 [1]–[15]）：**人味不是更流畅更聪明，而是「分布对齐 + 可控破绽」**——GPT-4 默认话语过关率 54%、加人格 prompt 后 73%（真人 67%）[31][32]；过于整齐（正式/非人称/低词汇多样性）本身是 AI 指纹 [33]；不流畅标记（犹豫/填充词）可提升拟人感知 [34]；一致性失败直接摧毁可信度（不一致降 55%+ 的 RL 工作以 prompt-to-line/line-to-line/Q&A 三指标为奖励）[36]；真实学习者的失联行为有统计分布（hint 滥用 18–37%、求助回避 11%）[38][39]；回复延迟呈倒 U 型且随人群调节 [42][43]；believability 四要素（人格一致/有情绪/目标驱动/会变化）源自 Oz Project [40][41]。

| 判据层 | 平台现状 | 差距评估 |
| --- | --- | --- |
| 语言学层 | 长度裁剪、口语字数约束（goal 靠 prompt）；无 disfluency/惯用语设计 | **空白**：无 AI 指纹规避、无套话清洗；cropReply 反而可能制造整齐感 |
| 行为层 | friction 五档+行为菜单、six Traits 话语锚点（4/6）、TalkMoves 式分布未对标 | 中：有受控随机，但话语动作分布未对齐真实学生语料 |
| 记忆层 | 四态代码裁决、私有状态与外显解耦、storyHistory 投影、previousLearnerState 回灌 | **领先**：外部角色扮演产品无「记忆认知置信度」概念；缺口在 CONFUSED 不可达（V-D7）与装配层 |
| 心理层 | masteryProb 带口径、struggle/known 台账、判错降级 | 部分：失联行为（help abuse/avoidance、gaming）未进行为菜单；request_hint/request_example 动作已有但无分布约束 |
| 节奏层 | 无回复延迟工程；teaching 回合即时返回 | **空白**：批跑场景影响小，但「真人感评测」场景（驾驶舱观看）下「秒回」是机器感来源 |

## 5. 外部工程对照（酒馆类 + 数字人/记忆 agent，详见 _vl-05/_vl-06）

### 5.1 四个最重要的可借鉴共识

1. **注入三旋钮**（何时/多少/哪里）：SillyTavern World Info 的触发键组+token 预算+插入深度+sticky/cooldown/delay 时间窗，与 AI Dungeon「常驻/触发/近因」三分层是角色扮演界对「全量锚定」的成熟替代。平台 personaAnchorHint 每轮全量注入可**无损映射**到这套旋钮（恒等核心低深度常驻 + 状态提示频率化 + 情节设定触发式；disclosurePlan 逐条映射 sticky/cooldown/delay）。
2. **show 优于 tell**：ST mes_example 示例对话（可挤出预算）+ Character.AI 官方定位「greeting 是最强风格锚」——平台完全缺示范话语层，开场白目前是确定性模板句（V-D8），恰好是最佳的 greeting-as-anchor 落点。
3. **护栏分档**：ST Regex 五位置硬护栏（含显示层/提示层分离）+ STscript 管线 vs 平台「检测后补救」单档；NovelAI Phrase Bias 是生成端方案。三字组兜底可升级为「检测→重采样→注入纠偏 hint→记 audit」管线。
4. **记忆高频小步**：Mem0 fact 级 ADD/UPDATE/DELETE/NOOP 冲突消解、Zep 双时间轴（t_valid/t_invalid 过期不删除）、Letta sleep-time 异步重组与 pinned block——共同点：**记忆维护是高频小步操作而非低频整篇重写**；memory-curate 的一次性策展模式是主要代差。AI Town 的 `NUM_MEMORIES_TO_SEARCH` 预算回放是 session-resumed 的现成方案；Nemesis 的「记忆外显为具体痕迹」天然反重复。

### 5.2 平台独有优势（外部没有的）

四态记忆认知置信度（CLEAR/VAGUE/CONFUSED/FAILED 代码裁决）、判决器与叙事器分离（epistemic-grounding 独立 skill + 强制覆写）、摩擦预算的编排层可测采样、actor-audit 事后保真审计、referee 独立旁路裁判——这套「评测面向的仿真」架构比外部角色扮演产品（面向沉浸感）多出整整一个治理层。
