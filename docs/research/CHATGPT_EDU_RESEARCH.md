## 二、核心功能

### 2.1 教师版专属功能

| 功能 | 描述 |
|------|------|
| **高级AI模型** | 无限访问GPT-5.1 Auto等旗舰模型 |
| **数据分析** | 上传Excel/CSV等文件，进行数据分析和可视化 |
| **网络搜索** | 实时网络浏览和搜索 |
| **深度研究(Deep Research)** | 自动搜集和分析多个信息源 |
| **文件上传** | 支持PDF、Word、图片等多种格式 |
| **图像生成** | 使用DALL·E创建教学图像 |
| **Custom GPTs** | 创建和分享自定义GPT |

### 2.2 Custom GPTs（自定义GPT）

**定义**: 通过配置系统提示词（System Prompt）和行为设置，定制化的GPT助手

**与传统ChatGPT的区别**:
| | 传统ChatGPT | Custom GPTs |
|--|------------|------------|
| **行为** | 每次对话需要重新引导 | 预配置的固定行为和工作流 |
| **一致性** | 可能不一致 | 保证响应一致性 |
| **记忆** | 只在会话内记忆 | 可以记住预设指令 |
| **用途** | 通用对话 | 特定任务/场景 |

**Custom GPTs创建方式**:

1. **通过UI创建**（No-code）
   - 设定名称和描述
   - 编写System Prompt
   - 选择模型能力（浏览、文件上传等）
   - 上传知识库文件
   - 设置图标和配色

2. **通过API配置**
   ```yaml
   name: "数学辅导员"
   description: "专精初中数学的AI教师"
   instructions: |
     你是一个初中数学老师，擅长用生动的例子讲解。
     遵循苏格拉底式教学法，不直接给答案，而是引导思考。
     回答应简短简洁，不超过200字。
   tools:
     - web_search
     - file_upload
   knowledge_base:
     - 七年级数学教材.pdf
     - 几何定理库.pdf
   ```

### 2.3 工作区与协作

- **学校工作区**: 学校内教师间的安全协作空间
- **共享Custom GPTs**: 将自定义GPT分享给同事
- **项目协作**: 共同编辑和创作教学资源
- **数据隐私**: 符合FERPA（美国教育隐私法）
- **管理员控制**: 学校IT可管理使用情况

## 四、技术架构推测

### 4.1 Custom GPTs本质

**不是训练新模型**，而是：

1. **System Prompt Injection**
   - 每次API调用时，插入预配置的System Prompt
   - 例如：`"你是一个数学老师..."`

2. **RAG ( Retrieval Augmented Generation)**
   - 上传的文件被索引成向量数据库
   - 每次查询时检索相关片段
   - 结合到Prompt中

3. **Function Calling / Tools**
   - 配置可使用的工具（网络搜索、文件上传等）
   - 模型可以选择调用这些工具

4. **对话历史管理**
   - 在会话内保持上下文
   - 但跨会话无状态（除非额外配置）

### 4.2 推理流程

```
用户输入
  ↓
[获取Custom GPT配置] - System Prompt + 知识库 + 能力
  ↓
[检索知识库] - RAG: 找到相关文档片段
  ↓
[构建完整Prompt] - System Prompt + 知识库片段 + 用户输入
  ↓
[调用GPT模型] - GPT-5.1 Auto
  ↓
[工具调用] - 如需网络搜索或文件上传
  ↓
返回结果
```

### 4.3 成功优势与局限性

**优势**:
- ✅ **快速创建** - 几分钟搭建，无需训练
- ✅ **低成本** - 不需要GPU，使用现成API
- ✅ **易分享** - UI配置，一键分享
- ✅ **灵活性** - 可以随时修改Prompt和知识库
- ✅ **质量控制** - OpenAI托管，稳定性好

**局限性**:
- ❌ **不是真正训练的模型** - 只是Prompt包装
- ❌ **行为受限** - 受基础模型能力的限制
- ❌ **一致性难保证** - 仍可能产生意外输出
- ❌ **推理速度** - 每次都需要完整推理，无模型优化
- ❌ **依赖OpenAI** - 数据和调用都在OpenAI平台

## 五、与我们要做的平台对比

### 5.1 核心差异

| 维度 | ChatGPT Edu (Custom GPTs) | 我们的平台 (AI模型部署) |
|------|-------------------------|------------------------|
| **AI教师本质** | GPT-5 + 定制Prompt | 训练过的独特模型 |
| **开发方式** | 配置System Prompt + 上传文件 | 训练/微调模型权重 |
| **技术栈** | OpenAI API + RAG | PyTorch + vLLM部署 |
| **定制深度** | Surface（行为和知识） | Deep（模型能力本身） |
| **性能** | 通用模型，中等速度 | 专用模型，可优化 |
| **数据隐私** | 数据在OpenAI平台 | 数据在自己平台 |
| **成本** | 按API调用付费 | 部署成本+推理成本 |
| **开发者能力** | 不需要编程 | 需要ML/AI专业知识 |
| **时间投入** | 分钟级 | 天到月级 |

### 5.2 应用场景差异

#### ChatGPT Edu适合的场景:
- 快速原型验证
- 不需要高度专业化的通用AI
- 没有GPU资源的小团队
- 需要快速迭代和实验

#### 我们的平台适合的场景:
- 高度专业化的学科模型（如深度数学、物理模拟）
- 需要特定教学风格的模型（如苏格拉底式、探究式）
- 数据隐私要求高（学校私有化部署）
- 需要推理性能和成本优化
- 想拥有完全自主的模型能力

## 七、混合模式的思考

### 7.1 可以结合两种方式

我们的平台可以同时支持：

**方式1: Custom GPTs模式（轻松定制）**
- 适合快速上手的开发者
- 只需配置Prompt和知识库
- 使用平台托管的通用模型
- 低门槛，低成本

**方式2: 定制模型模式（深度定制）**
- 适合有ML背景的开发者
- 训练/部署自己的模型
- 使用GPU推理
- 高定制，高性能

**平台可以自动选择**:
```
开发者上传 → 检测模型类型
  ↓
[是训练模型?] → 部署专用推理服务
  否
[是Prompt配置?] → 创建Custom GPT
```

### 7.2 API统一接口

无论底层是定制模型还是Custom GPT，上层API应该一致：

```python
# 用户调用，不关心底层实现
model = platform.get_model("math-tutor")

# 可能是训练的模型
# 也可能是Custom GPT
# 统一的响应格式
```

## 八、总结

### 8.1 ChatGPT Edu的核心价值

- **降低门槛** - 让非技术教师也能创建定制AI助手
- **快速迭代** - 分钟级创建和测试
- **标准化** - 统一的工作区和协作
- **免费推广** - 在教育界推广AI应用

### 8.2 对我们的启发

1. **用户体验很重要** - 简单的配置流程
2. **分享和协作** - 开发者之间的知识共享
3. **渐进式深度** - 从简单配置到复杂训练
4. **合规性** - 教育隐私和保护

### 8.3 我们的定位

**不只是Custom GPTs平台，而是真正的AI模型平台**

- ✅ 支持Custom GPTs模式（降低门槛）
- ✅ 支持定制模型部署（深度定制）
- ✅ 提供基础设施（训练、推理、监控）
- ✅ 开源生态（社区共建）
- ✅ 高性能推理（vLLM优化）
