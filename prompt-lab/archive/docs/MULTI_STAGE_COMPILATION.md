# 多阶段编译流程

## 概述

我们已经实现了一个 **3 阶段编译流程**，为未来的 6 阶段架构打下基础。

```
Stage 2: 蓝图层      Stage 3: 验证层      Stage 5: 编译层      Stage 6: 后处理层
   (Blueprint)    →   (Validation)   →   (Compilation)  →  (Post-processing)
       ↓                   ↓                   ↓                   ↓
   YAML 蓝图          静态检查           生成 Markdown         格式优化
```

### Stage 3: 验证层 ✅
**文件**: `frontend/src/utils/blueprintValidator.ts`

**职责**: 编译前的静态检查

**验证内容**:

#### 1. 基础字段验证
- `blueprintId` 不能为空，只能包含小写字母、数字、连字符
- `archetype` 必须是有效值
- `name` 不能为空
- `version` 建议添加

#### 2. 身份定义验证
- `identity.role` 不能为空，建议不超过 50 字符
- `identity.mission` 不能为空

#### 3. 规则验证
- `max_questions_per_turn` 范围 1-5
- `evaluation_mode` 必须是 `fresh_turn` 或 `continuation`
- `fabrication_policy` 必须是 `forbidden` 或 `allowed`
- 禁止编造时建议提供回退策略

#### 4. 输出规格验证
- `output.format` 必须是 `json`/`markdown`/`text`
- JSON 格式建议定义 `top_level_fields`
- 建议明确是否允许包装符

#### 5. Archetype 特定验证
- `conversational` 建议定义状态机和行为规则
- `generator` 必须定义输出格式

#### 6. 约束验证
- 检查重复约束
- 确保是数组类型

**返回结果**:
```typescript
{
  valid: boolean,
  errors: ValidationError[],    // 错误（阻止编译）
  warnings: ValidationError[]   // 警告（不阻止编译）
}
```

**使用示例**:
```typescript
const result = validateBlueprint(blueprint)

if (!result.valid) {
  console.error('验证失败:', result.errors)
  // 阻止编译
}

if (result.warnings.length > 0) {
  console.warn('警告:', result.warnings)
  // 继续编译，但提示用户
}
```

### Stage 4: 优化层 ✅（新增）
**文件**: `frontend/src/utils/b`blueprintOptimizer.ts``

**职责**: 编译前的自动优化

**优化内容**:

#### 1. 去重约束
```typescript
// 移除重复的约束
constraints: ["约束1", "约束2", "约束1"]  // 重复
↓
constraints: ["约束1", "约束2"]
```

#### 2. 自动推断缺失字段
```typescript
// JSON 格式自动添加禁止额外文本
output: { format: 'json', wrapper: false }
↓
output: {
  format: 'json',
  wrapper: false,
  forbidden_extra_text: ['前言', '解释', '总结', ...]
}

// 默认 wrapper 为 false
output: { format: 'json' }
↓
output: { format: 'json', wrapper: false }
```

#### 3. 根据 Archetype 补全
```typescript
// conversational 自动添加规则
archetype: 'conversational'
↓
archetype: 'conversational'
rules:
  context_usage: { ... }  // 自动添加
  behavior: { max_questions_per_turn: 1 }  // 自动添加

// generator 自动添加严格模式
archetype: 'generator'
output: { format: 'json' }
↓
output: { format: 'json', strict_schema: true }

// extractor 默认 JSON
archetype: 'extractor'
↓
output: { format: 'json' }
```

#### 4. 优化规则顺序
```typescript
// 按推荐顺序重排
rules:
  state_machine: {...}
  behavior: {...}
  context_usage: {...}
↓
rules:
  context_usage: {...}  // 推荐顺序
  behavior: {...}
  state_machine: {...}
```

**返回结果**:
```typescript
{
  optimized: YamlBlueprint,  // 优化后的蓝图
  changes: [
    {
      type: 'added' | 'removed' | 'modified' | 'merged',
      field: 'output.wrapper',
      description: '默认不使用包装符',
      after: false
    }
  ]
}
```

**使用示例**:
```typescript
const result = optimizeBlueprint(blueprint)

console.log('优化变更:', result.changes)
// 使用优化后的蓝图进行编译
const markdown = compileBlueprint(result.optimized)
```

### Stage 5: 编译层 ✅
**文件**: `frontend/src/utils/blueprintCompiler.ts`

**职责**: 生成 Markdown 提示词

**编译规则**:
1. 生成 Frontmatter
2. 展开身份定义
3. 生成执行规则（自动编号 RULE-XX）
4. 生成输出规格（自动编号 OUT-XX）
5. 生成边界约束（自动编号 CON-XX）

---

### Stage 6: 后处理层 ✅（新增）
**文件**: `frontend/src/utils/promptPostProcessor.ts`

**职责**: 对编译产物进行格式化和优化

**处理内容**:

#### 1. 统一换行符
```typescript
// CRLF → LF
text.replace(/\r\n/g, '\n')
```

#### 2. 移除多余空行
```typescript
// 连续 3+ 空行 → 2 空行
text.replace(/\n{3,}/g, '\n\n')
```

#### 3. 确保编号连续
```typescript
// 重新编号 RULE-XX, OUT-XX, CON-XX
// RULE-01, RULE-02, RULE-03...（确保连续）
```

#### 4. 添加元数据注释
```markdown
<!-- Generated by Blueprint Compiler -->
<!-- Compiled at: 2026-06-26T08:00:00.000Z -->
<!-- Compiler version: 3.0.0 -->
```

#### 5. 验证编译产物
```typescript
validateCompiledPrompt(markdown)
// 检查：
// - frontmatter 存在
// - 必要章节存在
// - 编号连续
// - 无过多空行
```

#### 6. 生成编译报告
```typescript
{
  linesCount: 103,
  charactersCount: 5432,
  rulesCount: 15,
  outputRulesCount: 4,
  constraintsCount: 3,
  sectionsCount: 5
}
```

## 完整编译流程

### 代码实现

```typescript
// stores/promptLab.ts
function compile() {
  if (!yamlBlueprint.value) return

  try {
    // Stage 3: 验证
    compileStatus.value = 'validating'
    validationResult.value = validateBlueprint(yamlBlueprint.value)
    
    if (!validationResult.value.valid) {
      // 验证失败，阻止编译
      compileStatus.value = 'error'
      compileError.value = validationResult.value.errors[0].message
      return
    }
    
    // 显示警告（不阻止编译）
    if (validationResult.value.warnings.length > 0) {
      ElMessage.warning(`${validationResult.value.warnings.length} 个警告`)
    }

    // Stage 5: 编译
    compileStatus.value = 'compiling'
    const rawMarkdown = compileBlueprint(yamlBlueprint.value)

    // Stage 6: 后处理
    compiledPrompt.value = postProcessPrompt(rawMarkdown, {
      addMetadata: true,
      normalizeLineBreaks: true,
      removeExcessiveBlankLines: true,
      ensureSequentialNumbering: true
    })

    // 验证编译产物
    const promptValidation = validateCompiledPrompt(compiledPrompt.value)
    if (!promptValidation.valid) {
      console.warn('编译产物验证失败:', promptValidation.issues)
    }

    // 生成报告
    compilationReport.value = generateCompilationReport(compiledPrompt.value)
    
    compileStatus.value = 'success'
    ElMessage.success('编译成功')
  } catch (error) {
    compileStatus.value = 'error'
    compileError.value = (error as Error).message
  }
}
```

```typescript
async function fullCompile(blueprintId: string): Promise<string> {
  // Stage 2: 加载蓝图
  const blueprint = await loadBlueprint(blueprintId)
  
  // Stage 3: 验证
  const validation = validateBlueprint(blueprint)
  if (!validation.valid) {
    throw new ValidationError(validation.errors)
  }
  
  // Stage 4: 优化（新增）
  const optimization = optimizeBlueprint(blueprint)
  console.log('优化:', optimization.changes)
  
  // Stage 5: 编译
  const rawMarkdown = compileBlueprint(optimization.optimized)
  
  // Stage 6: 后处理
  const finalMarkdown = postProcessPrompt(rawMarkdown)
  
  return finalMarkdown
}
```
