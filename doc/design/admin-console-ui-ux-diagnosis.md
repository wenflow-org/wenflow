# 问流 Admin 控制台 · UI 视觉与交互体验诊断报告

> 诊断对象：`/admin/:page`（16 个页面：总览、用户、学习者中心、教学会话、目标对话、反馈中心、虚拟学习者、Skill 目录、Agent 拓扑、编排结构、执行日志、Trace 瀑布、模型与接入、公告、外挂能力、核心文件同步。Prompt 调用已并入执行日志、事件中心已下线、外挂组件更名为外挂能力）
>
> 诊断视角：纯 UI 视觉、排版布局、交互动线（不涉及业务逻辑与数据口径）
>
> 当前设计语言基线：`mk-` 风格 —— 每页顶部"状态条"，主体为"卡片 + 紧凑表格"，蓝色主色 + 绿/琥珀/红状态色，mono 字体点缀技术字段

---

## 1. 整体视觉与排版诊断

### 1.1 信息密度：整体合格，列表页偏"重"

| 页面类型 | 密度评价 | 说明 |
|---|---|---|
| 总览（Dashboard） | 偏高 | 首屏同时出现 6 个 KPI、健康分、待办、漏斗、脉搏、趋势、用量、动态 9 个信息单元，虽然卡片化降低了压迫感，但同一屏内注意力被切分过碎 |
| 列表页（用户/目标对话/学习者中心） | 偏重 | 7–8 列表格 + 双行单元格（主标题+副标题），13px 基准字号下每行信息点 6–9 个，扫描成本高 |
| 观测页（执行日志/事件中心） | 合适 | 单行日志流密度合理，是最接近"现代运维产品"的页面 |

核心结论：**不是"内容太多"，而是"没有给内容分层"**。所有列表单元格几乎同等权重（标题 600 号、副标题 11.5px 灰、状态小徽章），缺少"焦点行"机制。

### 1.2 视觉噪音：三处主要来源

1. **导航红色徽章常亮脉冲**（`MockShell.vue` 的 `mshell-alarm-pulse`）
   只要近 7 天有失败，侧栏"执行日志"徽章就持续 `box-shadow` 脉冲动画。一次点击排查后它依然在闪，等于系统在持续"喊叫"却不接受"已读"。**红色告警动画应只用于"新出现"的事件，可平息（点击后降级为静态红点或灰点）。**

2. **mono 字体被过度使用**
   Trace ID、agent ID、时间戳、阶段名、版本号、甚至错误码全部 `JetBrains Mono`。mono 的本意是"技术字段一眼可识别"，但全页 mono 后它与正文的对比度反而消失，视觉上变成"灰蓝色字符墙"。**建议 mono 只保留在真正需要对齐/复制的字段（ID、耗时、token 数），时间戳与状态改用正文字体。**

3. **状态颜色语义重叠**
   失败用红 `#dc2626`、漂移/降级用深琥珀 `#b45309`。两者都是暖色系、色相接近（色弱用户几乎无法区分），且"漂移""降级""失败""超时"四个概念在六个页面里混用同一套色板（见 2.3）。**需要"形状 + 颜色"双通道编码（如漂移用虚线描边徽章、失败用实心），而不是只靠颜色深浅。**

### 1.3 空间利用：双滚动条是最大结构性问题

- 表格容器普遍 `max-height: 68vh + overflow-y: auto`（教学会话、Skill 目录、Prompt 调用），执行日志是 `72vh`，事件中心无上限。**同一套页面，滚动边界不统一，用户对"哪里会滚"没有稳定预期。**
- 由此产生"页面滚动 + 表格内滚动"双滚动条：滚轮悬停在表格上时只滚表格、页面不动，表格滚到底后滚轮"卡住"，用户会反复在两者间移动鼠标。这是 B 端最经典的反模式之一。
- 总览 3 列等高 grid 中，"总结产出质量"与"LLM 用量"卡片内容短，被拉伸后底部留白 40–60px，视觉上"卡片内空一大块"。

### 1.4 视觉层级：主次关系模糊

- **状态条元信息与标题同权**：每页状态条里 `标题`(13px/700) 与 `元信息`(12px 灰) 字号接近，用户第一眼抓不住"这页最重要的数字"。如学习者中心"6 位学习者需要关注 / 18 位学习者 / 需关注 6 / 低置信 18"四个数字并列，其中"低置信 18"比标题更醒目却语义最弱。
- **主操作不唯一**：状态条按钮（蓝实心）是页面主 CTA，但同一屏内行内 `mk-link` 蓝色文字按钮满天飞（详情/编辑/重算/删除/导出），视觉权重与主 CTA 拉不开。用户无法靠"颜色深浅"快速定位唯一的主操作。
- **整行可点与仅按钮可点并存**：教学会话/目标对话整行可点击进入详情，用户页只能点"详情"按钮——同一体系内交互模型不统一。

## 2. 易用性与交互痛点清单（Top 3）

### 痛点 1：长列表"假滚动真卡顿"，且无法稳定定位

**现象**：目标对话一次渲染 48 行、执行日志 200 行（已加"加载更多"但首次仍渲染 50 行、事件中心 80 条事件一次性铺满）；列表在容器内滚动。

**为什么不好**：
- 200 行展开行（payload 详情）同时挂载在 DOM 上，展开一条卡一次；
- 容器内滚动导致：刷新/筛选变化后回到顶部，用户已定位的位置丢失；无法使用"查看当前第几屏"的页码心智；
- "加载更多"按钮位于滚动容器底部，用户必须滚到底才能触发，且每次只加 50 条，在 200 条日志里要滚 4 次才看完，**操作成本与数据量线性增长**。

**好的设计解法**（三选一，按投入排序）：
- 短期：列表页改为整页滚动（去掉表格容器 max-height），"加载更多"按钮置为吸底（sticky bottom）或在按钮旁显示"还剩 N 条"；
- 中期：给可排序字段（时间、耗时、节点）加服务端排序，让用户"先缩小范围再看"，减少滚动量；
- 长期：日志流采用虚拟滚动（windowed rendering），只渲染可视 20 行；目标对话/用户等实体列表用真正的分页器（每页 20，带总数与页码）。

### 痛点 2：行内操作"四按钮平铺"，危险操作与无害操作同权

**现象**：用户列表每行同时展示 `详情 | 编辑 | 设为管理员/降级 | 删除` 四个文本按钮，删除是红色文字，与详情同一字号同一间距；目标对话行内 `重建路径 | 删除` 亦然。

**为什么不好**：
- 尼尔森原则第 6 条"识别胜于回忆 + 错误预防"：删除这类不可逆操作应"慢半拍"出现（hover 或菜单内），平铺 = 高频点击区 25% 面积是危险区，误触概率高；
- 操作列宽不定：按钮多时（4 个）操作列被撑到 300px+，挤压数据列；测试账号/他人账号还会动态增减按钮（3 个/2 个），行与行之间操作列宽度跳动，视觉不稳定。

**好的设计解法**：
- 行内只保留最高频操作（详情 / 查看）；
- 次要操作收进行尾 `⋯` 图标菜单（Menu），菜单内"删除"靠下并以红色 + 删除图标标注（危险区与安全区分组）；
- 或者统一为 hover 行时显示操作（参考 Linear / Vercel 的 hover reveal），桌面端省掉常驻视觉噪音。

### 痛点 3：状态语义多套话术并行，颜色无法承载全部信息

**现象**：同一套后台存在 4 套状态体系——
- 教学会话：已完成 / 超时 / 已暂停 / 已被替代 / 已废弃；
- 目标对话：进行中（阶段"澄清中"）/ 已完成 / 已取消；
- 执行日志：成功 / 失败 / 降级；
- 事件中心 / Trace：成功 / 失败 / 漂移；
且"降级 / 漂移 / 超时 / 已暂停"四个概念全部落在琥珀色系上。

**为什么不好**：
- 用户无法建立"状态 → 颜色 → 下一步行动"的稳定映射：看到琥珀色要分辨它到底是"要重试""要观察"还是"已被处理"；
- 对色觉障碍用户（红绿色弱占人口 8%）红/琥珀基本无法区分，纯靠颜色传达状态等于抛弃这批用户；
- 同一状态的标签文案在不同页面不同（如"已暂停"vs"暂停中"），搜索记忆不连贯。

**好的设计解法**：
- 收敛为统一状态模型：`成功(绿) / 处理中(蓝) / 警告(琥珀，需观察) / 失败(红，需行动) / 已终止(灰)` 五态，全站共用同一套徽章组件与字典（已有 `statusText.ts` 的基础，继续把文案统一）；
- 徽章加 icon 点或形状差异：失败=实心红点、警告=空心琥珀点、处理中=旋转 loading 点；
- 给关键状态徽章加 tooltip 解释"下一步建议"（如"超时：已自动重试 2/3 次"）。

## 3. 模块化 UI 改造建议

### 3.1 搜索 / 筛选区：统一为"搜索框 + 折叠高级筛选"

现状：筛选控件散落在状态条（执行日志的 pills + 节点下拉 + 时间下拉 + 关键词 + 自动刷新 + 导出，一行塞 6 组控件，在 1440px 下已换行）与卡片头部（目标对话的 pills）两处，位置不统一。

建议：

```
┌────────────────────────────────────────────────────────────┐
│ 🔍 搜索…                          [状态: 全部 ▾] [更多筛选 ▾] │   ← 常驻行：仅 搜索 + 主筛选
├────────────────────────────────────────────────────────────┤
│ [节点 ▾] [时间窗 ▾] [仅失败] [仅漂移]         已筛选 12 / 48 │   ← 展开"更多筛选"后的次级行
└────────────────────────────────────────────────────────────┘
```

- 每条筛选规则带可清除的 `×`（有筛选时出现），并显示"已筛选 N / M"；
- "自动刷新""导出"这类**非筛选控件**移出筛选区，放状态条最右或卡片头部（它们是动作，不是过滤条件）；
- Skill 目录的时间窗下拉补前缀标签"统计窗口："，避免裸下拉无上下文。

### 3.2 数据表格区：列宽、对齐、状态三件套

**列宽分配**（统一约定）：
- 固定列：复选框 32px、操作列 72–120px（图标按钮则 56px）、状态 96px —— 永不压缩；
- 弹性列：名称/摘要用 `minmax(180px, 1fr)`，摘要默认 2 行 clamp + `title` 全文；
- 数字列：`font-variant-numeric: tabular-nums` + 右对齐（现有 `mk-num` 已是正确方向，推广到所有数值列：耗时、token、调用数、失败数）；
- 时间列：统一 `11.5px` 灰、不换行、右对齐靠表尾（时间是人类扫读的"锚点列"，应贴边）。

**状态标签**：统一五态组件（见 2.3 解法），文案、色值、图标全部从单一字典输出，禁止页面内联写死颜色。

**排序与筛选的可视化反馈**：
- 排序列头带箭头（已有雏形），**筛选生效时表头加浅蓝背景 + 列内出现小漏斗图标**；
- 当前"仅看需关注""待关注"这类 pills 的激活态只是白底卡片，切换后用户看不到"结果集变了多少"——补一行结果摘要（"仅失败：42 条，较全部减少 12 条"）。

### 3.3 操作按钮区：三级权重体系

| 级别 | 样式 | 适用 |
|---|---|---|
| 主 CTA（每页 ≤1 个） | 蓝实心 `#3478f6` 白字，圆角 8px | 新建用户、全部重算、连接并拉取、立即探测 |
| 次操作（每屏 ≤2 个） | 白底灰边 ghost | 刷新、导出、重建路径 |
| 链接跳转 | 蓝色文字，仅用于导航 | 去排查、查看 Skill →、在瀑布中查看 |

- 行内操作一律收敛到 `⋯` 菜单（删除类放菜单底部、红色、带图标）；
- 危险操作再确认弹窗从 `window.confirm` 升级为页面内 Modal（样式与现有 `mk-modal` 一致），并写明后果与影响数量（"将删除 3 个用户及其学习记录，不可恢复"），这比浏览器原生 confirm 更有品牌感也更防误触。

## 4. "现代化"视觉风格升级建议（2026 SaaS 观感）

### 4.1 分层与阴影：从"描边盒子"到"悬浮层级"

现状几乎所有元素都是 `border: 1px solid #e1e8f2` 描边，页面像"网格纸"。

建议：
- 卡片：取消常驻边框，改用 `box-shadow: 0 1px 2px rgba(15,23,42,.04), 0 1px 3px rgba(15,23,42,.06)`；hover/选中时提升到 `0 8px 24px rgba(15,23,42,.10)`，**用阴影深度表达层级，而不是用边框描边**；
- 表格行分隔线从 `#f0f2f5` 降为更淡的 `#f6f7f9`，hover 用浅蓝 `#f6f9ff`（已有）保留；
- 侧栏与顶栏保留毛玻璃（已有 `backdrop-filter`），这正是现代 SaaS 的标志性质感。

### 4.2 色彩体系：一个品牌蓝 + 一个渐变强调色

- 主蓝 `#3478f6` 保留为"品牌动作色"，但只在可点击元素上出现（按钮、链接、激活态）；**标题、图标、边框不要再滥用蓝色**；
- 引入 1 个品牌渐变用于"大数字/健康分/活跃度"类展示元素（如 `linear-gradient(135deg,#4f8cff,#6a5cff)`），让总览页的 KPI 从"同色块阵列"变成"有层次的数据仪表"；
- 状态色改为"淡底 + 深字"双 token（已有雏形：`--mk-green-bg` / `--mk-green`），新增深色模式时只需换 token 值；
- 背景 `#f6f8fc` 偏冷蓝灰，建议统一为中性 `#f7f8fa`，让蓝色元素更突出。

### 4.3 圆角与字体

- 统一圆角阶梯：控件 8px、输入框 8px、卡片 12–14px、弹窗 16px、徽章 999px（现状已基本一致，做一次全局 token 化即可）；
- 字体栈升级：`Inter` + 中文字体补 `system-ui, "PingFang SC", "Microsoft YaHei"`（已有类似栈，统一到一个变量）；
- 数字全部 `tabular-nums`（已做），**正文行高 1.5 → 1.6**，13px 小字号下可读性提升明显；
- 标题阶梯固定为 11/12.5/13/16/18/22 六档，禁止页面内联再定义字号。

### 4.4 动效与空状态

- **骨架屏（Skeleton）替代 spinner**：live 数据加载时按表格行骨架展示（3 行灰条），比居中"加载中…"更符合"数据即将出现"的预期；
- 筛选/排序结果变化加 120ms 的 `opacity + translateY(4px)` 过渡，让"结果集变了"这件事可见；
- 空状态升级：图标 + 一句话解释 + 一个 CTA（如反馈中心空态加"去发布一条公告""导出模板"类引导），现状纯文字空态像"系统出错了"；
- 深色模式：侧栏/顶栏已用半透明背景，设计 token 全部走 CSS 变量（`mk-` 系列已是变量），补一套 `data-theme="dark"` 变量组即可低成本支持。

### 4.5 无障碍底线（可并入验收标准）

- 正文 13px 以下灰字 `#8492ab` 在白底对比度约 3.4:1，不达 WCAG AA（4.5:1），小字号辅助文本建议加深到 `#64748b` 级别；
- 键盘可达性：`⌘K` 命令面板是亮点（保留），补充焦点可见环（`outline: 2px solid` 而非仅变色）；
- 所有图标按钮补 `aria-label`（部分已有，做一次全覆盖检查）。

## 5. 二级页面与弹窗/抽屉走查（补充审计）

> 本章基于对 4 个二级详情页（用户详情 / 学习者详情 / 虚拟学习者画像 / 会话座舱）、6 类覆盖层（详情抽屉 ×3、Skill 抽屉、命令面板、通用弹窗）与 Skill 设计页的源码审计 + 实机走查。**结论：一级页面的问题在覆盖层和二级页被进一步放大，且存在几处一级页面看不到的严重问题。**

### 5.1 覆盖层（抽屉/弹窗）系统性缺陷：焦点管理完全缺失

这是本次审计最严重的发现——**全部 10 个覆盖层没有任何焦点管理**（实测教学会话抽屉：打开后焦点留在背景表格、无 `aria-modal`、背景滚动未锁定）：

| # | 问题 | 影响 |
|---|---|---|
| 5.1-1 | 打开后焦点不移入、关闭后不回落（全站仅命令面板做了 focus） | 键盘用户打开抽屉后 Tab 会"穿"到背景页面；读屏无 `aria-modal` 无法隔离上下文 |
| 5.1-2 | 背景滚动未锁定（`body` 无 overflow 锁定） | 抽屉内滚到底后滚轮继续滚动背景表格，"双滚动条"现象在弹层场景更严重 |
| 5.1-3 | 遮罩关闭用 `@mousedown.self`（按下即关） | 在抽屉内选中文本拖动到遮罩松手会**误关抽屉**，6 处覆盖层全部如此 |
| 5.1-4 | **Skill 抽屉跨页面常驻**：切换导航后抽屉仍打开并拦截侧栏点击（实测点击侧栏被抽屉遮挡、连续点击失败） | 用户从 Skill 目录打开抽屉后无法直接切换页面，必须先 Esc，动线断裂 |
| 5.1-5 | 多层覆盖层同时打开时 Esc 无停止传播（调色板 + 抽屉会一起关闭）；`⌘K` 在输入框内也会触发 | 误关闭、快捷键与输入冲突 |

建议：抽一个 `useOverlay` 组合式函数统一管理——打开时记录 `document.activeElement` 并聚焦面板、`aria-modal="true"` + 焦点圈定、锁定背景滚动、关闭时恢复焦点与滚动、遮罩改 `@click`（或 mousedown/up 均在遮罩才关）；Skill 抽屉在路由切换时自动关闭。

### 5.2 二级详情页：骨架体系断裂 + 兜底数据"张冠李戴"

四个二级页（用户详情、学习者详情、虚拟画像、会话座舱）共用组件（`AdminConsole.vue` 的 subPage 机制），但骨架完全不统一：

| 页面 | 页面标题 | 状态条 | 返回按钮文案 | 实测确认 |
|---|---|---|---|---|
| 用户详情 | 无（h3 与卡片标题同级） | ❌ 无 | ← 用户 | ✅ |
| 学习者详情 | 无 h1 | ❌ 无 | ← 学习者中心 | ✅ |
| 虚拟画像 | h2（唯一） | ❌ 无 | ← 返回列表（与其他页不一致） | ✅ |
| 会话座舱 | 无 h1 | ✅ 有（唯一合格） | ← 画像（**从会话座舱返回的其实是虚拟学习者列表，文案歧义**） | 源码确认 |

更严重的问题：

- **未知 ID 时展示另一个人的数据**（`MockLearnerDetail`/`MockVirtualProfile` 的 `find(...) || [0]` 兜底）：用户打开一个已删除/失效的详情，看到的是列表第一项（陈晓/vl-001）的数据——**数据真实性错误，比"显示空态"更危险**，必须改为"未找到"空态；
- **失败反馈用错语义色**：学习者详情重算失败显示绿色成功 toast（`mk-toast--ok` 固定渲染）；用户详情许可读取失败用蓝色 info 底——错误信息不能是绿/蓝色；
- 会话座舱是最合格的二级页（状态条、按钮 tooltip、轮询不跳滚动都在线），但其黑盒模式游标误导（不可点阶段 Tab 仍显示 pointer）；
- 详情加载失败大量静默降级（catch 吞错，用户不知道看到的是兜底数据）。

### 5.3 Skill 设计页（编辑器）：复杂度与脏数据风险

- **未保存草稿无离开保护**：切换 Skill / 刷新 / 关闭页面静默丢全部编辑内容（无 `beforeunload`、无 dirty 确认）——编辑器类页面最不该发生的事；
- 概览加载失败 = **空白页且无重试按钮**（刷新按钮只在有数据时才渲染，死锁）；
- "协议"页签 6 张表单卡全量平铺（实测 11 个 textarea 同屏），无折叠；输出字段行有无 label 的裸复选框（窄屏表头隐藏后完全失义）；
- 编译失败只有 3 秒 toast，错误无处可读（与保存失败的行内诊断不一致）；
- **发布守门（系统最严肃的流程）用原生 `window.confirm`/`window.prompt`**——与全站设计语言割裂；
- 三套并行原语：`mk-` / `sdp-` / `msk-`（同页面两种按钮、三种 pills 近同实现），后续维护成本高；
- 失败态被伪装成空态：工作台接口报错显示"未发现核心文件"。
- **亮点**：`?tab=protocol` 深链动线完整、版本页签行级 diff（含行号/±/折叠）是全站 best practice。

### 5.4 一致性账本（覆盖层/二级页专属）

- 抽屉宽度 4 档（460/540/560/600px）无理由；关闭按钮 28/30px、`✕`/`×` 混用；z-index 200/300 两套；
- 代码井配色两套（`#0d1420/#8ba3c7` vs `#101826/#9db8dc`）；
- `window.confirm` 全站 18 处（覆盖层 15 + 设计页 4），无一使用设计系统弹窗；
- 无 label 裸 checkbox、无键盘可达的故事卡（div 整卡 click 无 role/tabindex）、窄屏 facts 网格不塌缩（pcl 4 列在 360px 每格 70px 不可读）；
- `mock-shared.css` 文件头中文注释 mojibake（编码损坏），影响维护。

### 5.5 会话链路（sessionId）数据流（2026-08 打通）

业务会话（教学 / 目标对话 / 路径 / 模拟学习者）的调用跨多个 trace，需按会话归组排查。链路如下：

1. **注入**：`ai-teaching.routes.ts`（handleStreamingMessage / handleStreamingSession / 开场白补注入）、`goal-conversation.ts`（conversationId）、`learning.ts`（withPathContext + 4 路由）、`virtual-learners.ts`（router.param 统一注入）调用 `setRequestContext({ sessionId, ... })`；`acp-context.middleware.ts` 已为每个请求建立 AsyncLocalStorage store；
2. **透传**：`skills/executor.ts` executionContext 与 `recordSkillSpan` metadata 取 `parentContext.sessionId || contextEnvelope.session?.sessionId`（曾因 contextEnvelope 覆盖注入值导致 skill 行丢失，已修复）；api-gateway 行 metadata 直接读 `context.sessionId`；
3. **出库**：执行日志 API（`platform.ts /agents/logs`）经 `extractSessionIdFromMetadata` 输出 `sessionId` 字段；前端 `live.ts` spanOf 透传至 `TraceSpan.sessionId`；
4. **归组**：Trace 瀑布「会话」视图按 sessionId 聚合跨 trace span（时间轴以会话最早 ts 为起点），执行日志行内会话徽章 / 展开区按钮可直达；`intent.sessionId` 支撑深链跳转。

> 取舍：live 执行日志只落库单次调用（kind 恒为 `call`），不派生后端「流程」聚合行；会话级聚合由瀑布会话视图承担。
