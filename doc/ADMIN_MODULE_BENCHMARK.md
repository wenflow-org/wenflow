# Admin 模块级对标研究报告(2026-09-22)

> 定位:与 `ADMIN_PAGE_AUDIT.md`(静态审查)、`ADMIN_UI_WALKTHROUGH.md`(交互走查)互补的第三份报告——
> **逐模块与成熟产品对标**,评估功能布局差距,并结合 WenFlow「AI 教学模拟平台」的产品特色给出取舍建议。
> 性质:**纯研究报告**,不含代码改动。对标对象按域选择:Langfuse / LangSmith / Braintrust / promptfoo
> (LLM 观测与评估)、LiteLLM(LLM 网关)、Dify / Coze(工作流编排)、Ant Design Pro / GitHub Settings
> / Linear(后台布局体系)、Zendesk / Intercom(运营收件箱)、Duolingo for Schools(学习分析)。

## 0. 总览结论

1. **布局体系已对齐成熟后台**:状态条→指标→卡片→分页的解剖、列宽 token、响应式收敛完成后,
   剩余差距不在"布局乱",而在**功能深度**(对比矩阵/保存视图/预算告警三类)。
2. **对标后确认的三个共性缺口**(多模块共享,值得排期):
   ① 保存视图 / 自定义筛选(成熟观测平台的标准能力,我们的筛选都是一次性的);
   ② 实验/版本**对比视图**(PromptEval 与 Skill 版本都缺"和上一版比"的并排 diff);
   ③ **成本/预算告警**(有成本统计,无预算线与告警动作)。
3. **项目特色即壁垒,明确不建议抄成熟产品的**:观察模式归并审计、教学生命周期五阶段轴、
   契约级字段命中率、日期模拟与 autopilot、协议文件为真源的编排方式。成熟 LLM 平台没有这些。

## 1. 平台总览(观测域门户)

**现状**:结论先行(健康结论+行动卡置顶)、教学域指标(学习漏斗/总结产出质量/字段产出)——
是"结论先行"而非成熟产品的"图表先行";10s 自动刷新带断路器;全站跳转枢纽。

**对标**:Grafana(变量联动/自定义面板)、Langfuse Dashboard(时间范围/过滤联动/成本曲线)。

| 差距 | 分级 |
|---|---|
| 时间范围切换(现固定近 7 天/今日) | 🔴 值得补 |
| 图表点击即过滤(点柱子 → 该时段日志) | 🟡 |
| 自定义面板/保存布局 | ⚪ 运营规模不需要 |

**特色保留**:「需要关注:今日成功率 98.9%」这种**结论+行动项**置顶,优于 Langfuse 的图表罗列——教学运营者要答案不要仪表。

## 2. 用户与学习者

**现状**:账号/学习状态双 tab;筛选 pills 带计数;中屏断点;恢复用户走确认框。

**对标**:标准后台用户管理(Ant Design Pro / GitHub Settings);Duolingo for Schools(学习者进度视图)。

| 差距 | 分级 |
|---|---|
| 批量操作(批量改角色/导出选中) | 🟡 |
| 保存的筛选段(如"活跃教学者") | 🟡 |
| 用户级成本归因(每用户 token/费用) | 🔴(依赖成本归因数据,见 §12) |

**特色保留**:账号与"学习者"两种身份清晰分离,含虚拟/测试账号的口径标注——教学仿真平台特有。

## 3. 学习会话(教学会话/目标对话/学习路径)

**现状**:3 tab 宿主;教学生命周期五阶段轴(Goal→Path→Learn→总结);删除/恢复确认完整;
分页 26 页可达;仅真实/含模拟口径切换。

**对标**:Zendesk/Intercom 会话视图(时间线/标签/分派)、LangSmith session 聚合。

| 差距 | 分级 |
|---|---|
| 会话时间线可视化(阶段推进时刻轴) | 🟡(画像页已有 DayTimeline,入口可互链) |
| 筛选保存/分享 | 🔴(与 §0 共性缺口 ① 同) |
| 会话内消息级搜索 | ⚪ 数据在结构化字段,现有 keyword 已覆盖 |

**特色保留**:五阶段生命周期与 wrapup/收尾失败等状态族是产品语义,不套用通用 CRM 状态。

## 4. 记忆与复习

**现状**:概览卡(7 项 KPI)+ 用户列表(痕迹/到期/归并建议)+ 单用户明细(温故计划/同族重复/
归并审计)+ 观察模式(只记录建议,不写 memory_traces)+ 按次留档回滚。

**对标**:Anki 统计(保持率曲线/间隔分布)、FSRS 类工具;成熟 LLM 平台**无对应物**。

| 差距 | 分级 |
|---|---|
| 记忆保持率/到期曲线图表化(现为数字 KPI) | 🟡 |
| 归并审计的批量策略配置(阈值可视化调参) | 🟡 |

**特色保留**:「观察模式 + 可回滚留档」是memory 数据安全的正确姿势,成熟产品里罕见的严谨设计。

## 5. 虚拟学习者

**现状**:列表(10 列→窄屏 3 列)+ 画像详情(故事池/运行/日程/记忆池/画像 5 tab)+
会话座舱 + 运行/测试/删除操作 + 日期模拟 + autopilot。

**对标**:无直接成熟产品(合成学习者仿真属研究前沿:Stanford generative agents 一系;
产品化程度最高的是 synthetic-user 研究工具,均无后台管理体系)。最接近的交互范式是
A/B 实验平台的受众管理。

| 差距 | 分级 |
|---|---|
| 画像克隆/模板库(新建从既有画像派生) | 🟡 |
| 画像字段校验提示(悬空引用类问题的上游预防) | 🔴(与 §13 PromptEval 故障同根) |

**特色保留**:人设-故事-会话三层结构 + 需故事才能运行的守卫语义,是仿真域的产品核心。

## 6. 批量实验

**现状**:创建(人群+故事数+日程模拟)→ 服务端队列 → 进度条 → 卡死/失败管理;空态紧凑。

**对标**:Statsig/Eppo(实验分组与显著性)、AgentBench 类批跑工具。

| 差距 | 分级 |
|---|---|
| 多实验对比视图(指标并排) | 🟡(实验数少时收益低) |
| 实验结果摘要报告(自动生成结论段) | 🟡 |

**特色保留**:「创建人秒回、后台队列推进」的异步语义 + 失败重试(续传保留进度)已成熟。

## 7. 编排结构(编排拓扑/字段流转/沙盘/漂移)

**现状**:阶段 tab + 字段流转图(字段血缘/命中率/死字段)+ 漂移对账 + 治理折叠区;
编排以**协议文件为真源**,页面只读观测+字段路由编辑。

**对标**:Dify/Coze(可视化画布编排)、LangSmith(配置版本)。

| 差距 | 分级 |
|---|---|
| 画布式可视化编辑 | ⚪ **有意不做**——协议文件为真源是本项目的工程决策,画布会造成双真源 |
| 字段命中率的趋势对比(两版 prompt 之间) | 🟡 |
| 死字段一键下线建议 | 🟡 |

**特色保留**:「字段数据旅程」血缘视图在成熟 LLM 平台里没有同类物,是本项目观测深度的差异化。

## 8. Skill 运行

**现状**:健康检查/漂移/对账 4 tab;列表+网格双视图;完成度五档;健康点 aria 可达。

**对标**:LangSmith monitors、Langfuse model usage。

| 差距 | 分级 |
|---|---|
| 健康指标历史趋势(现仅当期窗口) | 🟡 |
| Skill 级成本归因 | 🔴(同 §2 成本归因) |

## 9. Prompt 评估

**现状**:用例库(启用/停用)+ 评估历史(30+ 条)+ 批量跑(模拟学习者模式:人设+故事+
多轮对话+摩擦预算);单用例支持 simulated 多轮 goal 循环。

**对标**:promptfoo(断言矩阵/多模型对比)、LangSmith datasets+experiments(版本对比、
annotation queue)、Braintrust(experiment diff)。

| 差距 | 分级 |
|---|---|
| 🔴 **悬空引用导致批量评估必失败**(走查发现,已修:跳过+报告) | ✅ 本轮已修 |
| 多版本 prompt 的评估结果**并排对比/diff** | 🔴 值得补(promptfoo/Braintrust 核心体验) |
| 每日自动回归(启用用例定时跑,失败告警进运营待办) | 🟡 |
| 人工标注评分 | ⚪ 单管理员场景收益低 |

## 10. 执行日志(日志/Trace/成本)

**现状**:服务端分页+筛选(状态/节点/测试三态已服务端化)+ Trace 瀑布 + 成本分析
(近 N 天/含模拟口径/按模型)+ 导出;错误码人话化。

**对标**:Langfuse(traces/sessions/scores/成本)、LangSmith(反馈打分)、Grafana explore。

| 差距 | 分级 |
|---|---|
| 保存视图/常用筛选 | 🔴(共性缺口 ①,高频页优先) |
| 成本预算线与告警(超阈值进运营待办) | 🔴(共性缺口 ③) |
| 时间直方图 + 框选联动列表 | 🟡 |
| trace 分数标注(人工评分挂到 trace) | 🟡 |

**特色保留**:字段命中率(契约层)是 Langfuse 没有的观测深度;错误归因分类(失败 TOP)
直接联动执行日志的动线已经对齐成熟产品。

## 15. 跨模块结论与建议排期

**P1(跨模块共性,建议合并排期)**
1. 成本/预算告警(§2/§8/§10/§12 四个模块的公共缺口):预算线 + 超限进运营待办。
2. 保存视图(§3/§10 优先):高频排查筛选可命名保存。
3. 评估对比视图(§9):prompt 版本间的并排通过率/字段命中率 diff。

**P2(单模块增值,按需)**:记忆曲线图表化、画像模板库、健康趋势、死字段下线建议、
待办内联处理。

**明确不做(项目特色即差异化)**:画布式编排编辑、会话状态套用通用 CRM、KPI 罗列式
总览(保持结论先行)、合成学习者的成熟产品式账号体系。

**证据链**:功能清单来自 `backend/src/routes/admin/*.ts` 全量端点提取(~250 端点);
布局与交互结论来自 2026-09-21/22 两轮真机走查(见 ADMIN_PAGE_AUDIT / ADMIN_UI_WALKTHROUGH)。
成熟产品基线:Langfuse / LangSmith / Braintrust / promptfoo / LiteLLM / Dify / Zendesk /
GitHub Settings(2026-09 官方资料与对比评测)。
