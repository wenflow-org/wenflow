# 路径场景中的 Anderson 标注迭代方向

## 背景

当前路径场景里的 Anderson 相关逻辑，已经从阻塞式后处理调整为路径可用后的 enrichment 阶段执行。

路径场景里需要区分两层语义：

1. 路径本体：阶段划分、阶段目标、任务顺序与任务内容。
2. Anderson 标注：对每个任务进行教育学定义，说明“在学什么、学到多深”。

## 当前分层

### 一阶段

一阶段是教育学定义层，主要输出：

- 任务更偏什么类型的知识
- 任务目标认知层级
- 任务学习目标
- 核心概念
- 可迁移性
- 标注置信度

这一层不是给用户看的主内容，而是给系统和后续教学场景使用的结构化定义。

### 二阶段

二阶段是展示翻译层，核心作用是把一阶段的教育学判断转成更容易被用户理解的短标签。

例如：

- 理解方法原理
- 动手实践
- 设计新方法

## 对当前路径场景的判断

### 一阶段输入是否够用

当前一阶段批量标注输入包含：

- 整体学习目标
- 用户背景摘要
- 领域/学科
- 所有任务列表
- 每个任务标题
- 每个任务描述
- 任务类型
- 所属阶段目标
- 目标类型分析给出的建议分布

结论：够用，但不算特别富。可以支撑当前的教育学定义任务，但后续如果要提升准确度，可以再补更强的局部上下文。

### 二阶段是否应独立存在

在路径场景中，二阶段当前只是将一阶段结果翻译成短标签，而这类翻译已经有稳定映射表。

结论：

- 路径场景里，二阶段没有必要继续逐任务单独调用
- 更合理的做法是：
  - 短期：直接使用本地映射表生成显示标签
  - 中期：如确实需要更贴场景的标签，可考虑在一阶段批量标注时一次性产出显示标签

## 推荐迭代方向

### 路径场景短期方案

- 保留一阶段批量标注
- 取消二阶段逐任务单独生成
- 显示标签由平台根据一阶段结果本地映射生成

### 路径场景中期方案

- 将一阶段与二阶段合并
- 由批量 Anderson 标注一次性输出：
  - 教育学结构化定义
  - 用户可读标签

## 对后续教学场景的启示

- 教学场景真正应该依赖的是一阶段的教育学定义
- 二阶段标签更适合作为用户理解和前端展示层
- 如果教学场景将来需要使用标签，也应优先考虑与一阶段同批产出，避免再做逐任务二次生成
