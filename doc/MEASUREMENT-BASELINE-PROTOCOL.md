# 测量基线协议（世代分界 + 快照冻结）

> 📌 类型：活规范（测量基线纪律；世代分界权威源=`backend/config/era-boundaries.json`）｜最后核验：2026-10-08。索引见 [doc/README.md](./README.md)。

- 发布：2026-10-08
- 范围：一切**以数据读数为依据的决策**——审计、复验、跑批读数、存量处置队列、A/B 对照、对外报告
- 一句话：**数据要有世代，决策绑定世代；基线是冻结产物，不是「再查一次库」**

## 一、问题：旧数据如何污染新决策

平台持续在修（`backend/src` 每次行为修复都会改变新写入数据的语义），但历史数据不会追溯改变。已实际发生的污染形态：

1. **修复前数据当现状**：C4 时钟修复前的复习样本，FSRS 间距被墙钟污染，混入曲线读数会整体偏乐观；
2. **旧世代机器判断进存量队列**：R7 概念键控上线前生成的 379 条归并建议，在键控语义改变后其判断依据已失效（2026-10-08 存量脚本直接执行的正是旧世代判断，已记教训）；
3. **参照系漂移**：VL 语料清单 38→40→45 条往返变更，跨批完成率/量级读数不可比；
4. **口径静默更换**：I2b 交付带新旧两版口径读数差异显著（<0.6× 42/88 条 → 61%），换口径不显式标注时，两版数字会被当成趋势；
5. **基线不可重演**：10-01 API 抽检（30 节）以「活查询」当基线，隔日复跑同口径得到不同样本集，两版读数无法逐条对照。

## 二、双轴模型：provenance × era

| 轴 | 回答 | 载体 |
|---|---|---|
| provenance | 数据从哪来 | 已有：脚本/通道/虚拟机标识（rw-* 等） |
| **era** | 数据属于哪个**行为世代** | 本文：`backend/config/era-boundaries.json` |

世代分界的唯一权威源是 `backend/config/era-boundaries.json`（File-as-Truth，先例：`llm-providers.json`）。登记规则：只登记**行为改变**（写入语义/调度语义/路由语义），不登记纯重构；`epochMs` 取生产生效时刻。读取用 `backend/src/config/era-boundaries.ts`（`eraOf` / `getEraBoundary` / `isAfterEra`）；脚本（.cjs/.mjs）直接 `JSON.parse` 同一文件。

**新增修复落地后登记一条边界是收尾动作的一部分**——与写单测同级，不登记等于让后续所有读数继续默认吃污染样本。

## 三、三条规则

### R1 冻结先于对照（freeze-before-compare）
任何「对比/趋势/进步了」的结论，其基线必须是**冻结产物**（快照文件），禁止以活查询当基线。复验=与快照逐条集合比对；基线本身要改，走版本升级（新快照，旧快照不删）。

### R2 世代过滤（era gating）
现状判断的读数默认**只吃最新相关边界之后**的数据；边界前样本单独成组（pre），不得与 post 混合进同一均线。跨世代对照必须**双列**（pre/post 显式分列，各自标 n）。脚本放弃过滤时必须注释显式声明原因。

### R3 执行前重算（recompute-before-execute）
基于读数生成的**存量处置队列**（归并建议/回填名单/清理清单），在执行前必须按**当前世代**重算；旧世代生成、跨过至少一条边界而未重算的队列，执行即违规。

## 四、基线快照格式

存放：`backend/scripts/measurement-verify/baselines/<id>.json`（读数脚本同域；聚合、脱敏，无 PII 原始行）。含原始行的临时快照只存 `doc/local/`（不入库）。

```json
{
  "schemaVersion": 1,
  "id": "i2b-delivery-band-2026-10-08",
  "capturedAt": "2026-10-08T14:00:00+08:00",
  "gitSha": "8d7ef13b",
  "era": "b2-backlog-disposition",
  "subject": "88 条 path 交付带 I2b 读数（口径：交付比 <0.6× 且 ratioCap<0.8）",
  "query": { "kind": "script", "target": "doc/local/tools/delivery-band-audit.mjs", "params": {} },
  "corpus": { "list": ["school-16", "..."], "hash": "sha256:..." },
  "rows": [ { "...": "聚合读数行" } ],
  "notes": "口径定义、已知污染与排除说明"
}
```

字段约定：
- `era` 必须由 `eraOf(Date.parse(capturedAt))` 得出（不得手写）；
- `gitSha` 记录冻结时的工作树 HEAD（`git rev-parse --short HEAD`）；若工作树有未提交改动，写入 `gitSha+` 并在 `notes` 列明；
- `query` 三型：`sql`（附完整 SQL 与参数，禁字符串拼接）、`script`（附脚本路径与参数）、`manual`（附操作步骤）；`target` 对 sql 型写库路径；
- `corpus.hash`：读数依赖语料/名单时的冻结指纹（清单变更=基线变更）；
- `rows` 只允许聚合值或脱敏行；任何含用户标识级别的行禁止入仓。

## 五、读数脚本自检清单

1. 头部输出 `[era] 主口径 = <boundary>（<at>，commit ...）...` 行（模板：`forgetting-curve-readout.cjs`）；
2. 每组读数带 `n` 与样本区间（如 `day1-19 共 84 对`），pre/post 显式分列；
3. 对照型脚本的基线从 `baselines/*.json` 读取并回显其 `id/capturedAt/era`；
4. 放弃 era 过滤的脚本，在注释与本清单说明理由；不得静默全量混算。

## 七、刻意不做

- 不做自动 era 推断（无隐式时钟魔法，世代必须显式登记）；
- 不给存量旧数据回贴新世代标签（旧数据就是旧数据，过滤而非重标）；
- 不接 CI 硬门禁（先人工纪律 + 脚本自检清单，门禁化待读数脚本全面模板化后再议）。
