# 系统虚拟学习者卡（200 张）

这 200 张卡来自 Frontier-100 评测基线，可直接在前端「卡库 → 导入卡文档」导入，作为任何部署的默认评测语料。导入后每张卡 = 一个系统虚拟学习者账号 + 一份档案 + 一个故事池，不需要改数据库、不需要跑脚本。

## 文件

| 文件 | 内容 |
| --- | --- |
| `virtual-learners-200.json` | **推荐一次性导入**：golden-100 + frontier-100 全量 200 张 |
| `golden-100.json` | 基准 100 张（A–E 五组：学科体系 / 工程实操 / 应试 / 业务诊断 / 边界负样本） |
| `frontier-100.json` | 前沿 100 张（F1–F5B：新规时效 / 技术版本 / 私有材料 / 专业深水区 / 诊断纠偏 / 分诊负样本） |

三个文件都是 `{ "version": 1, "cards": [...] }` 结构，前端导入页的 `校验` 与 `导入` 都直接支持。

## 前端导入

1. 打开管理端「虚拟学习者 / 卡库」页面，进入「导入卡文档」（`?view=card-import`）。
2. 拖入 `virtual-learners-200.json`（或两个分组文件之一），点「校验」。
3. 确认「可导入 200」、错误 0 后，点「导入」。
4. 「AI 补全人设」默认不勾：这些卡已带完整场景、目标、预算与追问，导入即可运行。需要更丰富的认知人设时再勾选（会逐卡调用 persona-designer，较慢）。
5. 重复导入时默认跳过同 `cardKey`；想用新版本覆盖，勾选「覆盖已存在的同 cardKey 卡」。

## 构成

- **100 张 golden**：覆盖系统掌握（mastery）与问题修复（repair）两类诉求，含 8 张分诊负样本（情绪/转介/不可判定场景）。
- **100 张 frontier**：F1 新规时效、F2 技术版本、F3 私有材料（F46–F65）、F4 专业深水区（F66–F85）、F5A 诊断纠偏（F86–F95）、F5B 分诊负样本（F96–F100）。
- **20 张私有材料卡（F46–F65）**：随卡内嵌 `materials`（内部手册/协议/规范节选 markdown），导入即写入该学习者的资料库，路径生成可直接走「附件主线」，无需再手工上传。
- **联网核验来源**：frontier 卡的 `story.goalSeed.webSource` 保留官方链接与核验事实，供溯源；情景本身是设计的，所以 `source.kind` 统一标为 `synthetic`（导入时会被标记为合成来源，这是预期行为）。

## 校验结果与预期告警

用后端 `validateCard` 逐张校验：**200 张全部可导入，0 错误**。两类告警是预期的，不影响导入：

1. **「合成来源将标记 isSynthetic」**：所有卡都是设计情景，`source.kind=synthetic` 是诚实标注。
2. **「预算不自洽」（47 张 golden）**：这些卡把 `expectedHours` 当作**内容体量锚**，而 `horizonDays × dailyMinutes` 是**日历容量**；两者按新时间模型本就相互独立（例如 6 小时的内容，分散在 105 天、每天 45 分钟的空闲里）。导入页的这条校验是 2026-10 初的旧口径，看到即可忽略。

## 字段约定

- `cardKey`：稳定 ID（`golden-*` / `frontier-F*`），也是重复导入的幂等键。
- `story.visibleOpening`：Goal 对话开场原话；`story.followUps`：后续三轮自动应答（不足 3 条的已按预算补一条时间安排追问）。
- `story.goalSeed.budget`：场景卡预算 `{ horizonDays, dailyMinutes, expectedHours }`，虚拟学习者链路会把它注入 Goal 开场并锚定 `objectiveScopeHours`。
- `story.goalSeed.expect`：`path`（应产出学习路径）或 `triage`（应走分诊负向出口、不生成路径），可供跑批脚本读取。
- `materials[].content`：随卡资料正文，导入时写入该学习者资料库。

## 删除与重导

这些卡导入后与普通自建卡无异，可在卡库逐张删除，或用管理接口按 `tags` 批量清理。重新导入同一文件时按 `cardKey` 跳过；要刷新内容需勾选「覆盖已存在」。
